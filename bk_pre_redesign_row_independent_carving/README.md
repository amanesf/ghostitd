# bk_pre_redesign_row_independent_carving/ (バックアップ)

このフォルダは、彫刻方式(front/side/back画像を行ごとに完全独立してサンプル
し、行間の連続性を一切見ない現行方式)の限界に突き当たり、根本から別方式を
検討することになった時点(2026-07-17)の、動作確認済みの状態をそのまま
保存したものです。

## 経緯(この時点で分かっていたこと)

スカート裾/腰・太もも・腕・頭頂等、パーツの輪郭が細くなる/複雑に変化する
箇所で、生成モデルにスパイク状の突起・裂けが発生する不具合を調査した。

- 間引き(decimateMesh)は既存の不具合を増幅する一因ではあるが、間引きを
  完全に無効化しても同じ破綻がほぼ同じ形で残ることを実データで確認済み
  (根本原因ではない)。
- 解像度(ボクセルサイズ)を4倍細かくしても同じ形の破綻が残ることを確認済み
  (解像度不足でもない)。
- 破綻箇所の三角形を調べると、近接し法線がほぼ逆向きな三角形ペア(表面が
  極端に密な間隔で折り返している=アコーディオン状のひだ)が集中している
  ことを確認済み。正常な細いパーツ(腕等)ではこのペアはほぼ0件。
- 元の色分けマップ画像そのものを確認したところ、画像自体はノイズではなく
  綺麗な絵柄だった。ただし側面画像を1行ずつ水平スキャンすると、腰のくびれ
  のような「シルエットの縁が両端から少しずつせり出してくる」形状で、
  1行に色の帯が複数出現することがあり、これを彫刻コードが「前髪のような
  別々の奥行き層が2つある」と誤って解釈し、そのまま激しい折り返しとして
  出力していた(js/carving.jsのcarveSdfField、複数帯×複数x区間の扱い参照)。
- 対策として (1) 間引き側の吸収集中対策(decimate_spike_guard)、
  (2) メッシュ空間での選択的平滑化(spikeSmoothSelective、Kホップ近傍平均+
  しきい値)を2種試したが、どちらも「一部の部位では効くが、別の部位(細い
  手足等)を巻き込んで壊す」という安全性の問題があり、両方撤回済み。
  現在のコードにはどちらも含まれていない(素の彫刻+間引きのみ)。
